# v7.1.13 operator guide

Preserve the existing installation, OAuth, enrollment, titles, local configuration and databases. Use the installer asset rather than GitHub's source ZIP for a new install. Healthy enrolled opted-in hosts follow v7.1.11 -> v7.1.12 -> v7.1.13 automatically through the retained signed baseline graph, waiting for safe empty-room controller transitions. This release changes controller/RPC code and requires a controller transition, not independent live replacement of occupied workers.

For an already queued v7.1.12 repair on a failed-but-running v7.1.11 host, first run the hash-checked one-time activation from https://github.com/Aves-Knoot/poolrotater-v7-pilot/releases/tag/v7.1.12 . Do not replace that protected queued job, repeat ownership-clear, reinstall or retry startup blindly. The v7.1.12 activation helper remains pinned to its original bytes. This successor is offered from the exact v7.1.12 baseline and does not bypass that step. A stopped service or uncertain ownership still requires its supported local review.

Default greetings are public player-facing text shared by maintainer request. An existing custom_join_greetings mapping is preserved; an explicit empty mapping disables defaults on that host. Built-in cooldown/silence remain. No owner OAuth, Discord token, AI configuration, role list or private integration files are distributed.

Player stats are local complete aggregate replicas, not on-demand requests to osu! or per-command hub calls. Ordinary totals refresh around every 20 minutes; short separate privacy authority is still required. Cold/expired-authority states fail closed and finish the original pending command automatically when ready. Keep the network agent running. Forward/backward wire/storage contracts and original opt-outs are preserved.

After actual activation return redacted support, update-status and network-support plus room links. Observe the retained notification socket/fallback and natural command responses. Publication/download alone does not prove activation or live gameplay acceptance. Retain all state and return refusal output if a transition fails.
