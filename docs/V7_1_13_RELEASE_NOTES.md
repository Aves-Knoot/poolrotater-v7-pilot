# v7.1.13 — community greetings and command responsiveness

Community rooms inherit the maintainer-approved six personalized player greetings when no local greeting mapping is configured. Explicit host mappings, including an empty opt-out, retain their meaning. Existing local configuration is never overwritten. A player whose username arrives through deferred profile enrichment can still receive their greeting once ready.

Live hosts defer optional profile/top-score GETs to one bounded read job per room. A separately bounded parent RPC lane handles only those two reads; chat, ownership, lifecycle and room mutations retain their serialized handler. The room thread alone applies results, preserving READY/playing state and discarding departed/rejoined players and old-room results. Typed transient failures retry; authority and unsafe/uncertain outcomes retain their fences. Provider request limits are unchanged.

Chat ACKs and incoming message reads have independent retry timers. Positively undispatched local pacing deferrals retry after one second instead of accumulating an extra 15-second exponential delay; network failures retain bounded backoff. Replies no longer sleep the room thread to satisfy the existing 1.5-second message spacing. A bounded queue preserves command-reply order and lets replies precede unsolicited reminders. Uncertain sends are never replayed; expiry, room/channel binding, silence and Discord routing remain.

Complete indexed Standard/Mania statistics replicas were already introduced in v7.1.11, with ordinary background refresh around 20 minutes. This release removes the writer reservation from command-side replica metadata reads and retains the original private-file/directory contract, current consent/epoch binding and 120-second privacy lease. Ready lookups, totals and visibility checks do no network I/O. Cold/unavailable lookups retain v7.1.12's automatic follow-up reply; outages or expired visibility can still delay a result.

The full-catalog real-worker/invented-provider test answered a command in about 1.24 seconds while its optional profile lookup remained deliberately blocked and a sibling 4K worker stayed alive. Local stats/visibility/status reads under an actual SQLite background writer completed in about 20–30 ms without HTTP or writer reservations. These are qualification measurements, not live-network latency guarantees. A protected v7.1.12-to-v7.1.13 upgrade preserved configuration, secrets, tuning, catalogs, ledger rows/schema, ownership, history and opt-outs. The final frozen affected suite passed 316 tests with no skips; the native full-catalog process and protected upgrade checks passed separately. Whole-repository suites and new actual-provider gameplay were not run.

This is a controller update with unchanged storage/dependencies. Existing hosts follow the signed exact-baseline chain and safe empty-room admission. An already-failed v7.1.11 host still needs the one-time v7.1.12 activation described in that release; publishing this successor does not remotely activate the old predecessor. No production room was manually restarted during development.
