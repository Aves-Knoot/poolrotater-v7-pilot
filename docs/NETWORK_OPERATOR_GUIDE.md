# Managed network participation

Enroll the existing instance with its private account/installation-bound
invitation. Return only the redacted network-support result and host ID.
Credentials and tokens stay on that host. Managed policy enables directory
capabilities, shared ratings/statistics, diagnostic/chat reporting, automatic
updates and central administration. Uploads still require authenticated hub
grants; configuration alone cannot grant contribution authority.

The independent network agent exchanges durable typed operations while room
workers are stopped. The fixed root reconciler can start an admitted controller
for an authorized room operation. There is no arbitrary remote-shell interface.
Public projections exclude private rooms and passwords; maintainer diagnostics
are separate private records. Existing deliberate room stops and local capacity
limits survive reconnection, recovery and upgrades.

The v7.3.3 candidate adds the `taiko-fixed` and `taiko-auto` presets. They use
qualified Taiko NoMod charts at normal rate with official Taiko difficulty and
verified source provenance for qualified conversions. Managed hosts download the full
qualified Taiko catalog through the pinned catalog source; existing room
presets do not change automatically. Keep bookings intact and use only free,
unreserved capacity for a Taiko pilot. New Taiko catalog fleet operations
require v7.3.3 or newer; older clients are refused those operations while the
five existing catalog modes and exact request retries remain supported. This
candidate has not completed installed acceptance, so these notes do not signal
that it is ready for deployment.

Use protected network-support, ratings-support, network-reporting-support and
managed-status for phases. A queued local event, hub acceptance, reader snapshot
and website publication are different stages. Keep state if delivery or room
ownership is uncertain. Follow MANAGED_HOST_ADMIN.md for exact room operations.
